# FactoryVision on Kubernetes

This directory contains the first Kubernetes deployment boundary for the
FastAPI inference service:

- `deployment.yaml` runs the API container, exposes `/health` probes, and
  defines CPU/memory requests and limits;
- `service.yaml` gives the API a stable in-cluster address on port `8000`;
- `configmap.yaml` supplies the non-secret serving configuration;
- `kustomization.yaml` groups the resources for one `kubectl` command.

## Local image and model prerequisites

Build the same image used by the Compose stack and make it available to the
local Kubernetes nodes:

```powershell
docker build --tag factoryvision-api:latest .
kind load docker-image factoryvision-api:latest --name factoryvision
```

The ONNX model is intentionally not committed to Git or copied into the
image. The Deployment expects the model file at:

```text
/mnt/factoryvision-models/factoryvision-segmentation.onnx
```

Make the host model directory available at that path using the mechanism of
the selected local cluster (for example, a kind `extraMount`, or `minikube
mount`). The directory must contain the model generated by
`python scripts/export_onnx.py`.

The ConfigMap currently points to a PostgreSQL Service named `postgres`, so a
PostgreSQL instance must be available in the cluster before the API becomes
ready. The credentials in this learning deployment match the local Compose
database and should be replaced with a Kubernetes Secret for a real deployment.

## Apply and test

```powershell
kubectl apply -k k8s
kubectl rollout status deployment/factoryvision-api
kubectl get deployment,pod,service factoryvision-api
kubectl port-forward service/factoryvision-api 8000:8000
```

In another terminal, verify the service:

```powershell
Invoke-RestMethod http://127.0.0.1:8000/health
Invoke-RestMethod http://127.0.0.1:8000/model-info
```

For a configuration-only validation without a cluster:

```powershell
kubectl apply --dry-run=client -k k8s
```
